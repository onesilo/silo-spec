# .silo Format Specification v0.1.0

## Status

Draft — v0.1.0

## Overview

A `.silo` file is a zip archive containing structured knowledge designed to be queried interactively by AI systems. It separates knowledge from the model that produced it and the application that stores it.

The format is implementation-agnostic. It defines the structure and semantics of the knowledge content. How that content is stored, indexed, and queried is determined by the reader.

## Terminology

The key words "MUST", "MUST NOT", "SHOULD", "SHOULD NOT", and "MAY" in this document are to be interpreted as described in [RFC 2119](https://datatracker.ietf.org/doc/html/rfc2119).

- **Writer** — an application that creates or exports `.silo` files.
- **Reader** — an application that imports or queries `.silo` files.
- **Memory** — an atomic unit of knowledge within a silo.
- **Entity** — a person, place, company, concept, or other named thing.
- **Relationship** — a typed, directional link between two entities.

## Versioning Rules

- The format version is declared in `manifest.json` via the `spec` field.
- New fields are additive only. A field introduced in a later version does not exist in earlier versions.
- Readers MUST ignore fields they do not recognize.
- Writers MUST NOT remove fields that existed in earlier spec versions.
- Breaking changes (removal of required fields, changes to field semantics) require a major version bump and a corresponding increase in `min_reader`.

---

## Package Structure

A `.silo` file MUST be a valid zip archive. It MUST contain the following entries at the archive root:

- `manifest.json`
- `silo.json`

It MAY contain:

- `refs/` — a directory of reference files

Readers MUST ignore unknown root-level entries.

```
example.silo (zip archive)
├── manifest.json
├── silo.json
└── refs/
    └── (optional files)
```

No embeddings, indexes, or platform-specific storage should be included in the package.

## manifest.json

The manifest provides metadata a reader examines before parsing the silo content. All dates are ISO 8601 strings. All identifiers are strings.

### Required Fields

| Field | Type | Description |
|-------|------|-------------|
| `spec` | string | Format version. `"0.1.0"` for this spec. |
| `min_reader` | string | Minimum reader version required to open this silo. |
| `id` | string | Unique identifier (UUID recommended). |
| `title` | string | Human-readable name. |
| `created_at` | string | ISO 8601 timestamp. |
| `updated_at` | string | ISO 8601 timestamp. |
| `mode` | string | Interaction mode. One of: `"container"`, `"augmented"`, `"open"`. |

### Optional Fields

| Field | Type | Description |
|-------|------|-------------|
| `description` | string | Short summary of the silo's contents. |
| `icon` | string | Icon identifier (system name or custom reference). |
| `creator` | object | See below. |
| `subject_entity_id` | string | Reference to the primary entity in `silo.json` this silo is "about." |
| `sharing` | object | See below. |
| `tags` | array of strings | Freeform labels. |
| `stats` | object | See below. |
| `extensions` | object | Arbitrary key-value pairs for app-specific metadata. Readers MUST ignore unknown keys. Recommended namespace: reverse domain (e.g. `"app.onesilo.access_roles"`). |

### creator

| Field | Type | Description |
|-------|------|-------------|
| `name` | string | Display name of the creator. |
| `uri` | string | Optional identifier or URL. |

### sharing

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `access_mode` | string | `"read"` | `"read"` or `"read_write"`. |
| `allow_reshare` | boolean | `true` | Whether the recipient may re-export. |

### stats

| Field | Type | Description |
|-------|------|-------------|
| `memory_count` | integer | Number of memories. |
| `entity_count` | integer | Number of entities. |
| `ref_count` | integer | Number of reference files. |
| `ref_size_bytes` | integer | Total size of reference files in bytes. |

### subject_entity_id

A silo MAY declare a subject entity — the primary thing it is "about." This is a reference to an entity `id` in `silo.json`.

Readers MAY use the subject entity for UI prominence, summary generation, or insight targeting. A silo with no subject entity is valid.

### Interaction Modes

The `mode` field defines how an AI reader should behave when answering queries against this silo:

**container**

The AI MUST answer using only content from this silo. If the requested information is not present, the AI MUST indicate the gap explicitly. The AI MUST NOT use general world knowledge or fabricate information.

**augmented**

The silo's content is the primary source. The querying user's personal context MAY fill gaps. The AI MUST NOT use general world knowledge. Inferences drawn from the user's context MUST be labeled as such.

**open**

The silo's content informs the answer. The AI MAY use its full capabilities including world knowledge. The AI SHOULD label which parts of the answer come from the silo versus other sources.

The mode is set by the creator. Readers SHOULD respect the declared mode. The mode MUST NOT be overridden by the recipient without the creator's consent.

## silo.json

The silo content file. Contains all structured knowledge.

### Top-Level Structure

All arrays are required but MAY be empty. The `config` object is required but MAY be empty.

```json
{
  "memories": [],
  "entities": [],
  "relationships": [],
  "topics": [],
  "memory_entity_links": [],
  "memory_ref_links": [],
  "refs": [],
  "config": {}
}
```

---

### memories

Each memory is an atomic unit of knowledge.

#### Required Fields

| Field | Type | Description |
|-------|------|-------------|
| `id` | string | Unique identifier. |
| `type` | string | One of: `"fact"`, `"decision"`, `"narrative"`, `"insight"`, `"open_item"`, `"custom"`. |
| `content` | string | The knowledge in natural language. This is what gets embedded and searched. |
| `created_at` | string | ISO 8601 timestamp. |
| `updated_at` | string | ISO 8601 timestamp. |

#### Optional Fields

| Field | Type | Description |
|-------|------|-------------|
| `metadata` | object | Type-specific fields. See below. |
| `updated_by` | string | Identifier of the last editor. |

#### Type: fact

Concrete, stated knowledge.

| Metadata Field | Type | Default | Description |
|----------------|------|---------|-------------|
| `key` | string | — | Short label (e.g. `"budget"`, `"destination"`). |
| `confidence` | number | 1.0 | 0.0 to 1.0. |
| `category` | string | — | Freeform grouping label. |

#### Type: decision

An explicit choice with reasoning.

| Metadata Field | Type | Description |
|----------------|------|-------------|
| `title` | string | Short description of the decision. |
| `alternatives_considered` | array of strings | Options that were evaluated. |
| `decided_by` | array of strings | Names or entity IDs of decision makers. |
| `decided_at` | string | ISO 8601 or date string. |
| `confidence` | number | 0.0 to 1.0. |
| `status` | string | `"final"`, `"tentative"`, or `"revisited"`. |

#### Type: narrative

A rich topic block — longer-form content organized by subject.

| Metadata Field | Type | Description |
|----------------|------|-------------|
| `title` | string | Section heading. |
| `topic` | string | Topic identifier or label. |
| `section_order` | integer | Sort position within the topic. |

#### Type: insight

Semantic reasoning about the silo's subject. Derived from patterns, not stated directly. Typically carries lower confidence than facts.

| Metadata Field | Type | Description |
|----------------|------|-------------|
| `title` | string | Short summary of the insight. |
| `confidence` | number | 0.0 to 1.0. |
| `supporting_memory_ids` | array of strings | References to memory IDs that led to this inference. |
| `category` | string | Freeform grouping label. |

#### Type: open_item

An unresolved question, task, or decision.

| Metadata Field | Type | Description |
|----------------|------|-------------|
| `priority` | string | `"high"`, `"medium"`, or `"low"`. |
| `status` | string | `"open"`, `"resolved"`, or `"cancelled"`. |
| `due_date` | string | ISO 8601 or date string. |
| `assigned_to` | string | Name or entity ID. |

#### Type: custom

An extension point for app-specific structured content.

| Metadata Field | Type | Description |
|----------------|------|-------------|
| `custom_type` | string | App-defined type identifier (e.g. `"workspace"`, `"health_summary"`, `"recipe"`). |
| `schema` | string | Optional identifier for the structure of the `data` field. |
| `data` | object | Arbitrary structured content specific to the `custom_type`. |

The `content` field MUST still contain a natural language summary suitable for embedding and search. Readers that do not recognize the `custom_type` SHOULD treat the memory as a generic content block using the `content` field.

### entities

Each entity represents a person, place, company, concept, or other named thing.

#### Required Fields

| Field | Type | Description |
|-------|------|-------------|
| `id` | string | Unique identifier. |
| `name` | string | Display name. |
| `type` | string | Entity type. Recommended: `"person"`, `"place"`, `"company"`, `"competitor"`, `"concept"`. Extensible. |
| `created_at` | string | ISO 8601 timestamp. |
| `updated_at` | string | ISO 8601 timestamp. |

#### Optional Fields

| Field | Type | Description |
|-------|------|-------------|
| `properties` | object | Arbitrary key-value pairs. Schema depends on entity type. |
| `alternate_names` | array of strings | Other names this entity is known by. |

Readers MUST tolerate unknown entity types.

There are no implementation-specific identity markers (such as "is_me" flags) in the entity model.

---

### relationships

Each relationship is a typed, directional link between two entities.

#### Required Fields

| Field | Type | Description |
|-------|------|-------------|
| `id` | string | Unique identifier. |
| `source_entity_id` | string | Reference to an entity `id`. |
| `target_entity_id` | string | Reference to an entity `id`. |
| `type` | string | Relationship type. Recommended: `"works_at"`, `"invested_in"`, `"competes_with"`, `"located_in"`, `"related_to"`, `"founded"`. Extensible. |
| `created_at` | string | ISO 8601 timestamp. |

#### Optional Fields

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `weight` | number | 1.0 | Strength or importance of the relationship. |
| `metadata` | object | — | Arbitrary key-value pairs. |

### topics

Topics provide hierarchical organization for memories.

#### Required Fields

| Field | Type | Description |
|-------|------|-------------|
| `id` | string | Unique identifier. |
| `name` | string | Topic name. |

#### Optional Fields

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `parent_id` | string | — | Reference to a parent topic `id` for hierarchy. |
| `sort_order` | integer | 0 | Sort position among siblings. |

### memory_entity_links

Links between memories and the entities they reference.

#### Required Fields

| Field | Type | Description |
|-------|------|-------------|
| `memory_id` | string | Reference to a memory `id`. |
| `entity_id` | string | Reference to an entity `id`. |

#### Optional Fields

| Field | Type | Description |
|-------|------|-------------|
| `role` | string | The entity's role in the memory. Recommended: `"subject"`, `"mentioned"`, `"decided_by"`. Extensible. |

---

### memory_ref_links

Links between memories and reference files.

#### Required Fields

| Field | Type | Description |
|-------|------|-------------|
| `memory_id` | string | Reference to a memory `id`. |
| `ref_id` | string | Reference to a ref `id`. |

#### Optional Fields

| Field | Type | Description |
|-------|------|-------------|
| `relationship` | string | How the ref relates to the memory. Recommended: `"supports"`, `"source"`, `"attachment"`. Extensible. |

---

### refs

Each ref catalogues a file in the `refs/` directory.

#### Required Fields

| Field | Type | Description |
|-------|------|-------------|
| `id` | string | Unique identifier. |
| `filename` | string | File name. |
| `path` | string | Relative path within the `refs/` directory. |
| `mime_type` | string | MIME type of the file. |
| `created_at` | string | ISO 8601 timestamp. |

#### Optional Fields

| Field | Type | Description |
|-------|------|-------------|
| `description` | string | Human-readable description. |
| `size_bytes` | integer | File size in bytes. |
| `data_summary` | object | Machine-readable summary of structured data files. See below. |

#### data_summary

For structured data files (JSON, CSV), a summary that helps an AI decide whether to read the file without opening it.

| Field | Type | Description |
|-------|------|-------------|
| `row_count` | integer | Number of records/rows. |
| `date_range` | object | `{ "start": "ISO 8601", "end": "ISO 8601" }` |
| `columns` | array of strings | Field or column names. |
| `source` | string | Origin of the data (e.g. `"healthkit"`, `"google_drive"`, `"plaid"`). |

---

### config

Runtime behavior configuration carried inside the silo. All fields are optional. An empty object is valid.

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `system_instructions` | string | — | Canonical LLM instructions for this silo, always injected into context. Defense-in-depth mode enforcement. |
| `mode_instructions` | string | — | Mode-specific enforcement prompt (container, augmented, or open). |
| `welcome_summary` | string | — | Short summary displayed on first open. |
| `welcome_message` | string | — | Creator-authored intro message for recipients. |
| `suggested_prompts` | array of strings | — | Starter questions for first-run experience. |
| `citation_required` | boolean | `false` | Whether the reader should require citations in responses. |

System instructions provide defense-in-depth mode enforcement. Even if a reader ignores the `mode` field in the manifest, the instructions embedded in context direct the AI's behavior.

---

## refs/ Directory

- MAY be absent if the silo has no reference files.
- Contains files referenced by `refs` objects in `silo.json`.
- File paths in `refs` objects are relative to this directory.
- No restrictions on file types. Recommended: PDF, images (PNG, JPEG), plain text, markdown, JSON, CSV.
- Readers SHOULD surface ref files alongside memories that link to them via `memory_ref_links`.

## Conformance

### Writer Requirements

- Writers MUST produce a valid zip archive with `manifest.json` and `silo.json` at the root.
- Writers MUST include all required fields in `manifest.json` and `silo.json`.
- Writers MUST set `spec` to the version of this specification they conform to.
- Writers MUST set `min_reader` to the minimum spec version a reader needs to meaningfully interpret the content.
- Writers MUST NOT include embeddings, indexes, or platform-specific storage in the package.

### Reader Requirements

- Readers MUST validate `spec` and `min_reader` before processing.
- Readers MUST ignore fields they do not recognize in `manifest.json`, `silo.json`, and all nested objects.
- Readers MUST handle all six memory types. Unknown types SHOULD be treated as generic content blocks.
- Readers SHOULD respect the declared `mode`.
- Readers SHOULD inject `config.system_instructions` into the AI context on every query.
- Readers SHOULD display `config.welcome_message` and `config.suggested_prompts` on first interaction.
